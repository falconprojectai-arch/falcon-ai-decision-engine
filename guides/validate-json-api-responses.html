How to Validate JSON API Responses Against a Schema

API integrations and AI agents often return JSON that is syntactically valid but structurally wrong. A response can parse successfully and still omit a required field, change a boolean to a string, or put the wrong type deep inside a nested object. A response contract catches these problems before downstream code relies on them.

1. Define the expected shape

For example, an endpoint might promise an object with a boolean ok flag, a non-empty string result, and metadata containing a request ID and non-negative integer retry count.

{
  "type": "object",
  "required": ["ok", "result", "meta"],
  "properties": {
    "ok": { "type": "boolean" },
    "result": { "type": "string", "minLength": 1 },
    "meta": {
      "type": "object",
      "required": ["request_id", "retry_count"],
      "properties": {
        "request_id": { "type": "string", "minLength": 1 },
        "retry_count": { "type": "integer", "minimum": 0 }
      },
      "additionalProperties": false
    }
  },
  "additionalProperties": false
}

2. Test more than one happy-path response

A useful batch should include at least one valid response and representative failures. For the schema above, try these JSON values (one per line):

{"ok":true,"result":"done","meta":{"request_id":"req-001","retry_count":0}}
{"ok":true,"meta":{"request_id":"req-002","retry_count":1}}
{"ok":"yes","result":"done","meta":{"request_id":"req-003","retry_count":0}}
{"ok":true,"result":"done","meta":{"request_id":"req-004","retry_count":"2"}}

The expected outcome is one pass and three failures: a missing required result, a wrong top-level type, and a wrong nested type. Testing a mixed batch is more revealing than checking only a single valid example.

3. Read failures as actionable diagnostics

For each failed sample, look for four things:

  • Sample index: which response in the batch failed.
  • JSON Pointer: the exact location, such as /meta/retry_count.
  • Expected: the contract rule or expected type.
  • Actual: the value or type received.

This makes it easier to identify whether the producer, adapter, prompt, or downstream mapping needs attention. It is especially useful when comparing many AI-agent outputs.

4. Know the limits of the validator

The free browser tool linked here supports a documented subset of JSON Schema: type, required, properties, additionalProperties: false, items, enum, const, numeric bounds, string length and pattern, and array length bounds.

Important: It is not a full JSON Schema implementation. It does not support $ref, $defs, allOf, anyOf, oneOf, not, format validation, boolean schemas, or schema-valued additionalProperties. Unknown keywords are ignored. A PASS only means the value matched the supported rules. Use a complete validator for full-specification, production-critical, or security-sensitive validation.

5. Keep sensitive payloads local

JSON Contract Tester runs validation in the browser. The page states that inputs stay in the browser and are not uploaded. Avoid pasting secrets into any online tool unless you have independently checked its data-handling behavior.
