How to Test AI Agent JSON Outputs in Batches

When an AI agent is asked to return structured JSON, a successful JSON parse is only the first check. The output may still omit a required key, return a number as a string, or change a nested object between runs. These failures can break tools, automations, and downstream API calls.

1. Define the contract your consumer expects

Start with the shape your application actually reads. For example, a support-triage agent might return a category, a confidence score, and a list of next actions.

{
  "type": "object",
  "required": ["category", "confidence", "actions"],
  "properties": {
    "category": {
      "type": "string",
      "enum": ["billing", "technical", "account", "other"]
    },
    "confidence": {
      "type": "number",
      "minimum": 0,
      "maximum": 1
    },
    "actions": {
      "type": "array",
      "items": { "type": "string" },
      "minItems": 1
    }
  },
  "additionalProperties": false
}

2. Build a repeatable batch

Do not test only one successful answer. Keep a small, representative batch that includes a valid result and likely structural failures:

{"category":"billing","confidence":0.94,"actions":["check invoice"]}
{"category":"technical","confidence":"high","actions":["open ticket"]}
{"category":"unknown","confidence":0.7,"actions":["request logs"]}
{"category":"account","confidence":1.2,"actions":[]}
{"confidence":0.8,"actions":["verify email"]}

For the contract above, the first object should pass. The other four should fail for a type mismatch, an enum violation, a numeric bound plus an empty array, and a missing required field.

3. Inspect the exact failure, not just PASS or FAIL

  • Sample index: identify which agent run produced the invalid structure.
  • JSON Pointer: locate the field, such as /confidence or /actions.
  • Expected vs actual: see the rule and the received value/type.
  • Repeatability: run the same batch after a prompt, schema, or model change.

This creates a lightweight regression check for output shape. It does not prove that the category is factually correct or that the agent followed the intended reasoning.

4. Separate structural validity from semantic quality

A response can satisfy every JSON rule and still be wrong. For example, "category":"billing" may be structurally valid but factually incorrect for the user's request. Combine contract validation with domain-specific assertions, human review, and end-to-end tests where needed.

5. Use a validator whose scope matches your schema

JSON Contract Tester is a free, local-browser utility for batch validation against a documented subset of JSON Schema. It supports types, required fields, properties, selected array and string constraints, enum, const, and numeric bounds. It does not implement the full JSON Schema specification: composition keywords such as oneOf, anyOf, allOf, not, references such as $ref, format validation, and boolean schemas are unsupported. Unknown keywords are ignored.

Important: A PASS means the value matched the supported rules only. Use a full JSON Schema validator for schemas requiring unsupported features or for production-critical/security-sensitive validation. Do not treat structural validation as a substitute for semantic evaluation.
